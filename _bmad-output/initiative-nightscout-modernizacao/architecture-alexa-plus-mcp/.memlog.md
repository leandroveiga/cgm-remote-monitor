- (direction) Modo Coaching; entregavel unico = spine; iniciativa initiative-nightscout-modernizacao; objetivo da modernizacao = habilitar a aplicacao para funcionar com Alexa+ (resposta do usuario 2026-10-21)
- (constraint) [ADOPTED] MCP Fase 1 ja existe: lib/mcp (McpServer, 6 tools read-only), lib/api/mcp (Streamable HTTP em /api/v1/mcp, sessoes em memoria, enableJsonResponse), habilitado por ENABLE=mcp; auth = ctx.authorization.isPermitted('api:*:read'). Nota: docs/proposals/alexa-plus-mcp-feasibility-analysis.md ainda afirma que nao ha codigo MCP (desatualizado).
- (constraint) [ADOPTED] Alexa classica (ASK) existe: lib/plugins/alexa.js + virtAsstBase.js + POST /api/v1/alexa; habilitada por ENABLE=alexa; coexistir sem regressao.
- (constraint) Sem testes para MCP (nenhum tests/*mcp*). Sem rate limit nem audit log. Sem OAuth2/OIDC; proposta oidc-actor-identity-proposal.md nao implementada. Sem spec publica oficial da Amazon confirmada para Alexa+ (pendente de fonte primaria).
- (constraint) Dados de saude sensiveis; app critico de saude; compat retroativa API v1 obrigatoria; AGPL-3.0; Express 4.17.1; mongodb ^5.9.2; ctx global; CommonJS JS sem TS.
- (version) Alexa+ MCP Toolkit (fonte oficial developer.amazon.com/docs/alexaplus/add-ons, doc atualizada jul-ago/2026): Alexa+ e o cliente MCP; suporta MCP spec 2025-11-25 sobre Streamable HTTP; disponivel apenas nos EUA; Alexa+ for Builders so para parceiros selecionados; deploy via Alexa AI CLI (alexa-ai deploy); mudancas de tools/auth exigem redeploy do add-on.
- (constraint) Auth Alexa+ MCP em 2 tiers: (1) client_credentials (scope mcp:service, token <=3600s, sem refresh_token, Basic auth, valida parametro resource) usado p/ initialize/tools/list; (2) authorization_code + PKCE S256 (scopes mcp:tools, mcp:resources) p/ tools com dados do usuario. Metadata do auth server deve listar client_credentials, authorization_code, refresh_token e S256. NAO suportado: DCR, OIDC, step-up, header WWW-Authenticate em 401.
- (constraint) Gap critico: Nightscout nao tem authorization server OAuth2 (/authorize, /token, metadata, PKCE, refresh). Auth atual = API_SECRET hash / access tokens JWT por subject. MCP atual faz initialize ja exigindo api:*:read, o que conflita com o tier-1 (service token sem dados de usuario).
- (constraint) Gap: Alexa+ cria add-on com design guide (voz/visual, MCP Apps opcional); respostas das tools devem ser desenhadas para fala (dados estruturados bem nomeados, unidades, tempo relativo). Tools atuais retornam JSON.stringify em content text, sem structuredContent/outputSchema.
- (question) Quem opera o authorization server: embutido no processo Nightscout, ou IdP externo (ex.: Keycloak/Auth0/Cognito) com Nightscout como resource server? Nightscout e self-hosted por milhares de usuarios individuais: como cada instancia se registra como add-on Alexa+ (1 add-on por instancia vs. 1 add-on multi-tenant)?
- (event) Iniciativa Alexa+ ABORTADA pelo usuario em 2026-10-21 (complexidade: exige servidor OAuth2 + programa restrito a parceiros/EUA). Spine nao produzido. Novo objetivo: manter Alexa classica (ASK custom skill) e habilitar em Echo Dot via AWS/Alexa Developer Console.
